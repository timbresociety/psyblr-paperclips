# I01 — Golden-loop integration owner

**Preferred model:** GPT-6 Astra, high
**Ownership:** shared contracts, state/reducer, shell, integration code and any merge conflicts. Feature folders should be changed only when a worker result is objectively broken.

## Inputs

Completed S01–S04 work. Read their diffs/results, not their chat histories.

## Goal

Produce one coherent first-customer loop using the improved Demand/Product/Monetisation rooms and the deterministic engine. Remove duplicate authority between fixture reducer and engine. Preserve the frozen semantic meanings unless a concrete integration defect requires a minimal change.

## Acceptance journey

From reset on desktop and mobile:
1. see one Demand signal and its cost/evidence;
2. qualify it through the real gesture;
3. cash decreases and Product work appears;
4. assemble a meaningful product;
5. verify and ship;
6. Monetisation becomes actionable;
7. commit price inside fit;
8. ARR/valuation change but cash does not;
9. collection occurs only at its due simulation time;
10. causal history explains each change.

Inspect the running app, not screenshots alone. Fix broken focus, overflow, pointer capture and mobile composition. Run `npm run check`.

Before declaring the loop complete, apply `context/REVIEW_RUBRIC.md`. Causality, Decision, Interaction Legibility and Mobile Composition may not score 0. Do not compensate for a weak interaction with decorative polish.

## Scope fence

No Retention, Expansion, Operations, agents, VC, relics or full balance work. If the first loop is not convincing, do not escape into later systems.
