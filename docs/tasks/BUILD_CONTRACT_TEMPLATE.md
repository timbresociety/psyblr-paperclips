# Build contract template

Use this only after discovery has converged. Do not fill unresolved product decisions with plausible guesses.

## Outcome

What should the player understand, feel or be able to do after this slice?

## Hypothesis

Why should this interaction/system produce that outcome?

## Predicted observable behavior

What should a first-time player actually do or correctly explain if the hypothesis is true?

## Starting state

Exact relevant state when the slice begins.

## Visible model

What must be visible before the player commits? Include costs, risk, deadlines and causal information that affect the decision.

## Interaction sequence

1. ...
2. ...
3. ...

Describe semantic intent, not implementation-specific pointer coordinates.

## State transitions

```text
ACTION
→ IMMEDIATE LOCAL RESPONSE
→ AUTHORITATIVE STATE CHANGE
→ DOWNSTREAM CONSEQUENCE
```

## Settled decisions

Only decisions explicitly established by product context or current user approval.

## Implementation discretion

Reversible choices the implementation agent may make without returning to discovery.

## Non-goals

Explicitly name adjacent systems/features that must not be added.

## Visual / interaction references

Name only references that materially constrain this slice and state the principle to learn from each.

## Acceptance

Observable running-product criteria. Include desktop and mobile portrait for visible work.

## Failure condition

What evidence would prove this design/build hypothesis wrong or too weak to continue?
