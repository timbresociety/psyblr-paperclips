# SoloUnicorn content and writing contract

## Voice

Write like a sharp founder who has lived through agent sprawl, bad dashboards, customer churn and a suspicious cloud bill. Be concise, specific, mechanically literate and funny when the situation earns it. Cultural references can reward recognition, but the consequence must remain clear without the reference.

Every player-facing unit follows:

```text
MECHANICAL TRUTH → CONTEXT → CULTURAL INTELLIGENCE → VOICE → JOKE
```

Avoid MBA filler, generic “AI-powered” language, motivational founder clichés, meme spam, unlicensed likenesses, copied slogans, protected characters and jokes that hide costs or probabilities.

## Deterministic content envelope

The engine creates an event before narrative rendering:

```json
{
  "event_id": "stable.id",
  "event_type": "approved.type",
  "eligible_entities": ["account-or-queue-id"],
  "option_ids": ["approved.option.a", "approved.option.b"],
  "effect_ids": ["approved.effect.id"],
  "numeric_preview": {"cost_cents": 0, "deadline_tick": 0},
  "seed_context": "replay-safe reference",
  "content_version": "v1"
}
```

GenAI may render title, flavour, context or post-result explanation from that envelope. It cannot choose a customer, reward, effect ID, number, probability, target, debt term, relic or success. A malformed/slow response falls back to authored local copy and cannot stall a deadline or reroll an event.

## Content objects

Every rank, strategy, relic, situation, request, obligation and tutorial has a stable ID, content version, plain effect summary, eligibility/trigger, approved effect IDs, exact values from the balance profile, downside, localization variables and provenance. Copy never hides mechanics.

### Relic interface

```json
{
  "id": "relic.example",
  "name": "original memorable name",
  "effect_summary": "plain-language result",
  "effect_id": "approved.effect.id",
  "eligibility_reason": "why this founder/build sees it",
  "tradeoff": "explicit downside or null",
  "rarity": "versioned content field",
  "build_tags": ["product", "automate"],
  "founder_success_required": true,
  "flavor": "optional"
}
```

Relics are contextual “What Changed?” moments. Specific catalogue, stacking and balance are deferred to a separate relic evaluation. Successful founders may own persistent effects; failed founders mint no new permanent power. Never normalize away the earned advantage.

### Quarterly strategy

A strategy has a thesis, duration, exact effects, costs, constraints, entry/exit rule, activation tick, build tags and failure interaction. It changes how the company runs, not just one anonymous scalar.

### Founder history

Founder history is player-selected and fictional. It can change starting options, relic eligibility, starting effects or early financing access. It never silently reads real identity, career or account data and never directly multiplies valuation.

## Function content

Author deterministic content for Demand signals, Product requirements/recipes, Monetisation offers, Retention threats, Expansion packages, Operations evidence/risk cards, Finance offers, ranks, strategies, founder history, tutorials, failure explanations and milestone beats. Each content item names its causal input, action, result and next pressure.

The six baseline interactions are Demand swipe/triage, Product semantic assembly, Monetisation price-fit timing, Retention aim/prioritisation, Expansion merge/package and Operations scratch/reveal/diagnosis. Finance uses selection and confirmation.

## Cultural transformation and IP safety

```text
RESEARCH PATTERN → MAP TO COMPANY DECISION → INVENT ORIGINAL FICTION
→ WRITE ORIGINAL COPY → CHECK MECHANICAL CLARITY AND IP SAFETY
```

Use current founder/AI culture in replaceable event packs and variants. Do not copy posts, lyrics, articles, protected game cards, third-party logos, celebrity/influencer likenesses or a creator's exact joke. Hindi/English variants are authored/reviewed language layers, never a hidden mechanics channel.

## Tutorials and failure copy

Teach `DO → SEE → NAME → COMBINE → COMPLICATE`. Each micro-tutorial has one cue, one action, one result and one consequence sentence. Failure copy names cause, onset, bottleneck, build and counterfactuals. It does not blame “bad luck” without showing the accepted exposure.
