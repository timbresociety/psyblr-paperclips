# Coding agent contract

This file governs agents implementing SoloUnicorn. It is subordinate to system/developer instructions and the actual owner request. Product rules are in `CONTEXT.md`; numerical rules are in `BALANCE.md` and `engine/`; execution routing is in `TERMINAL_AGENT.md`.

## Authority and conflict handling

Use this order:

1. Current explicit owner instruction.
2. Owner-confirmed entries in `DECISIONS.json`.
3. Recovered owner direction in `DECISIONS.json`.
4. This master context's detailed contracts.
5. Existing repository behavior, as implementation evidence only.

`archive/` or historical source material is not included as an active authority. A generated document cannot grant itself approval. Candidate numbers are delegated for implementation and tuning within the causal model, but do not describe them as play-balanced without evidence.

If a conflict changes the game premise, scoring, ARR causality, cash failure, continuous-time attention model, successful-founder progression or visual identity, stop that affected change and report the exact conflict. Continue independent work. Missing prices or incomplete content are bounded implementation work, not reasons to block the whole project.

## Non-negotiable product rules

- Build a one-person founder simulator with a constrained starting budget, progressively richer HUDs and a satisfying manual-to-agent arc.
- Valuation is the score. Cash is spendable currency. ARR is recurring customer revenue. Earned revenue and collected cash are separate.
- Six operating functions use the same four mechanical axes: Craft, Scale, Automate and Luck. Finance manages liquidity and financing; it is not a forced reflex activity.
- Growth failure is conditional on accepted VC terms. Cash failure is an unpaid mandatory obligation. Debt and VC create pressure, not free upgrade currency.
- The player has one founder attention stream. The company keeps simulating during work, inspection, Finance and post-quarter decisions unless explicitly paused.
- Scale and Automate must create costs/strain/rot that can accumulate. Operations repairs finite problems through actual work. Avoid arbitrary direct ARR taxes.
- Successful repeat founders are intentionally stronger. Never add a balancing cap or normalization layer merely to keep fresh runs equally difficult.
- Use React plus HTML Canvas in a responsive installable PWA. Preserve the existing stack unless the owner requests a migration.
- GenAI can produce contextual wording only after the deterministic engine fixes the event, options and effect IDs. Models cannot choose numbers, customers, rewards, probabilities or debt terms.

## Preflight before editing

1. Read the relevant master documents and identify the exact contract version.
2. Inspect repository instructions, current branch/commit, dirty state, scripts and existing implementation. Preserve unrelated work.
3. Map the requested outcome to one bounded task and named files. Identify state/schema ownership before assigning writers.
4. Run the smallest relevant tests first. Add or update a meaningful fixture when changing a ledger, event order, resolver, save migration or economic formula.
5. Write a checkpoint before context compaction, model handoff or a long task. Keep transient progress outside canonical product documents.

## Engineering rules

Keep economic logic in a headless deterministic engine. Click handlers, CSS, animation callbacks, frame rate, viewport size, wall-clock time, network results and generated prose cannot determine economic state. Use integer cents and integer simulation ticks, carried remainders and versioned seeded streams.

Every state change has one resolver, a stable event ID and an explanation. Repeated or stale actions are idempotent or rejected. Derived metrics cannot be directly set. Preserve origin-account lineage when splitting cohorts. Never count expected throughput as actual output, ARR or cash.

Run every scheduled phase in the order defined by `engine/event_contract.json`. Settle due obligations before milestone awards. A later receipt cannot rescue an earlier missed obligation. At identical timestamps, only the declared receipt/bill priority applies. Preserve RNG attempt IDs so opening a panel, resizing or rebatching does not reroll a result.

Use semantic action records for touch, mouse, keyboard and accessible alternatives. Pointer cancellation, lost capture, resize, backgrounding and reduced motion cannot double-book work. Finance transactions show cash required, recurring cost, payment dates, debt terms and dilution before confirmation.

## Agent delegation

Use the lowest-cost capable model. One agent is the default. Add one focused reviewer or up to two workers only when independent work has stable interfaces and real risk reduction. One lead owns shared schemas, event order, balance profile and integration.

Good splits include a visual gesture prototype against a frozen action interface, a bounded content batch against approved effect IDs, or an isolated test harness. Bad splits include multiple agents inventing churn/ARR rules, editing the same reducer, or authoring relic economics before effect IDs exist.

Workers return changed paths, tests, unresolved findings and dependency. The lead reviews actual diffs and runs integration gates. Do not create a swarm because the product has six functions. Context size, token use and merge risk count as engineering constraints.

## Completion standard

Report the exact milestone, files changed, balance/content/schema versions, commands run, tests and their results, replay seeds where relevant, screenshots/recordings where interaction matters, and remaining limitations. Keep “implemented,” “mathematically verified,” “playtested,” “balance validated” and “owner accepted” as separate statuses.

Do not push to GitHub, publish, install paid services, send messages or change global permissions unless the actual task explicitly authorizes that action. This context pack itself contains no such authorization.
